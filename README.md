# UNA

**UNA (Universal Native Arhivator)** — название более широкого проекта. В этом репозитории сначала разрабатывается алгоритм сжатия и его формат данных; готовое приложение-архиватор UNA — отдельный будущий этап.

## Что такое ANL сейчас

В проекте **ANL** — название разрабатываемого алгоритма сжатия и архивного представления данных. ANL9 0.9.3 — экспериментальный прототип этого формата с консольными программами для кодирования, структурной проверки и декодирования одного файла.

Это **ещё не готовый архиватор общего назначения**: сейчас нет упаковки каталогов и нескольких файлов в один контейнер, интеграции с оболочкой или стабильного пользовательского интерфейса. Наличие команд кодирования и декодирования показывает работу прототипа формата, а не завершённость продукта UNA.

## ANL9 0.9.3

Данные разбиваются на блоки по 64 КиБ. Формат поддерживает необработанные блоки, ссылки на ранее встречавшиеся одинаковые блоки и MiniBlock-записи с буквальными данными, обратными ссылками и повторами байтов. Заголовок и записи защищаются CRC32.

Версия ANL9 0.9.3 сохраняет значение поля формата `0x0902` для совместимости с архивами 0.9.2.

- `anlc93.c` — кодирование входного файла.
- `anlcheck93.c` — проверка структуры архива и CRC записей.
- `anlr93.c` — декодирование и проверка CRC восстановленного содержимого.

Проверка `anlcheck93` не восстанавливает содержимое и сама по себе не проверяет итоговую CRC файла; для полной проверки нужно декодировать архив.

## Сборка

Ниже команды, указанные в документации ANL9 0.9.3. Они рассчитаны на MSYS2 UCRT64 GCC и запуск из корня репозитория:

```sh
gcc -std=c17 -O2 -Wall -Wextra -pedantic -o ANL9/v0.9.3/anlc93.exe ANL9/v0.9.3/anlc93.c
gcc -std=c17 -O2 -Wall -Wextra -pedantic -o ANL9/v0.9.3/anlr93.exe ANL9/v0.9.3/anlr93.c
gcc -std=c17 -O2 -Wall -Wextra -pedantic -o ANL9/v0.9.3/anlcheck93.exe ANL9/v0.9.3/anlcheck93.c
```

Пример запуска:

```sh
ANL9/v0.9.3/anlc93.exe input.bin output.anl9
ANL9/v0.9.3/anlcheck93.exe output.anl9
ANL9/v0.9.3/anlr93.exe output.anl9 restored.bin
cmp input.bin restored.bin
```

## Ограничения прототипа

- Обрабатывается один файл за запуск; контейнера для каталогов и нескольких файлов пока нет.
- Кодировщик и декодировщик работают с данными в памяти.
- Декодировщик выделяет память под заявленный размер результата после проверки заголовка; прототип не следует считать безопасным сервисом для обработки недоверенных архивов.
- Заголовки и записи дают заметные накладные расходы на маленьких файлах; случайные данные могут увеличиваться в размере.
- Структурная проверка и проверка восстановленного содержимого выполняются разными программами.

В репозитории присутствует лицензия Apache-2.0.
